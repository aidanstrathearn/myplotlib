# cargo-myplotlib

`cargo-myplotlib` builds embeddable Myplotlib WebAssembly packages and complete
static sites. Install it from the Myplotlib checkout:

```sh
cargo install --path crates/cargo-myplotlib --locked --force
cargo myplotlib --version
```

Then run it as a Cargo subcommand:

```sh
cargo myplotlib build-web \
  --manifest-path examples/two_views/Cargo.toml \
  --out-dir examples/two_views/pkg \
  --release \
  --locked
```

The output contains a public `app.js` module, Myplotlib's private loader, and
the bindings and WebAssembly generated by wasm-pack. The host page imports
only `app.js`. The public module exports the cargo-myplotlib release version
and web package format alongside `mount` and `unmount`.

Add `--site` to put a minimal fullscreen host page directly in the output
directory:

```sh
cargo myplotlib build-web \
  --site \
  --manifest-path path/to/Cargo.toml \
  --out-dir dist
cargo myplotlib serve --dir dist
```

The generated `index.html` uses relative asset URLs, so the directory can be
served at a domain root or below another path. Site mode owns `index.html`,
`_headers`, and `coi-serviceworker.js`. It marks its generated files and will
replace only files carrying that marker; it refuses to overwrite hand-written
files with those names.

For a threaded application, let `cargo-myplotlib` select the tested nightly,
rebuild the standard library with atomics, and supply the shared-memory linker
configuration:

```sh
cargo myplotlib build-web \
  --site \
  --wasm-threads \
  --rayon-threads 12 \
  --manifest-path path/to/Cargo.toml \
  --out-dir dist
```

A threaded generated site requires an explicit positive `--rayon-threads`
count. That fixed value is embedded in `index.html`; the generated page does
not infer a count from `navigator.hardwareConcurrency`. Threaded package builds
without `--site` continue to leave thread selection to their host page.

The shared-memory maximum defaults to 1 GiB. Override it with
`--wasm-max-memory <BYTES>`; the value must be a non-zero multiple of 65536 and
cannot exceed 4 GiB. Threaded builds require this one-time machine setup:

```sh
rustup toolchain install nightly-2025-11-15 \
  --component rust-src \
  --target wasm32-unknown-unknown
```

`cargo-myplotlib` checks these prerequisites but never installs or changes a
toolchain. It uses the pinned nightly only for the threaded `wasm-pack` child
process, leaving the default toolchain and ordinary Cargo commands unchanged.
The application still opts into Rayon and exposes its pool initializer:

```toml
rayon = "1"

[target.'cfg(target_arch = "wasm32")'.dependencies]
wasm-bindgen-rayon = { version = "1.3", features = ["no-bundler"] }
```

```rust
#[cfg(target_arch = "wasm32")]
pub use wasm_bindgen_rayon::init_thread_pool;
```

After migrating, remove the thread-specific `.cargo/config.toml` and
`rust-toolchain.toml` from the application. Direct `wasm-pack build` no longer
supplies that configuration; use `cargo myplotlib build-web --wasm-threads`.

Serve the directory containing the host page with cross-origin isolation:

```sh
cargo myplotlib serve --dir examples/two_views --port 8080
```

The web root defaults to the current directory and the server listens on
`127.0.0.1:8080`. Every response includes COOP and COEP headers, allowing a
threaded application to use `SharedArrayBuffer` and initialize its Rayon pool.
Use `--host` to select another IP address. Loopback HTTP is suitable for local
threaded development; browsers generally require HTTPS when the page is opened
from another device over a LAN address.

For a threaded site, `--site` also generates a Cloudflare Pages `_headers` file
and a `coi-serviceworker.js` fallback for static hosts such as GitHub Pages that
cannot set the required response headers. The service worker requires HTTPS or
localhost and reloads the first visit once after it takes control. On
Cloudflare Pages or `cargo myplotlib serve`, the response is already
cross-origin isolated and the worker does not register. A later non-threaded
site build removes the generated hosting files and unregisters an earlier
Myplotlib isolation worker without touching service workers at other URLs.

This command expects `wasm-pack` to be installed. Its loader initializes Rayon
when the generated bindings export `initThreadPool`. Generated Wasm dependencies
use content-versioned URLs so the development server can reuse them across
worker contexts without serving stale assets after a rebuild.
